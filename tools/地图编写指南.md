# 桃园三国 · 地图编写指南（自然语言版）

这份文档讲清楚三件事：地图文件长什么样、人怎么走图/触发跳转、怎么自己动手画一张图（含室内图设计建议）。

---

## 一、一张地图 = 一个 JS 文件

每张地图是 `data/maps/` 下的一个 `.js` 文件，文件名就是地图的"身份证"（key），比如 `ch00_city.js`。文件里注册一个对象到全局 `MAPS`：

```js
MAPS["ch00_city"] = {
  name: "徐州城",            // 显示在屏幕顶部 HUD 上的地名
  grid: [ ... ],            // 地图本体：一串等宽字符串（重点，下面细讲）
  npcs: [ ... ],            // 站在图上的 NPC
  chests: [ ... ],          // 宝箱
  transitions: [ ... ],     // 传送点（走上去切图）
  triggers: [ ... ],        // 触发器（踩上去触发剧情/战斗）
  signs: [ ... ],           // 建筑招牌（可选）
  tileOverrides: [ ... ],   // 条件地块（可选，如藏宝洞口）
  encounterTiles: ["."],    // 在哪些格子上会随机遇敌（可选）
  encounterRate: 0.12,      // 遇敌率（可选）
  encounterGroups: [...],   // 会遇见哪些敌人（可选）
};
```

**grid 是核心**：它就是一个字符画。每个字符占一格（游戏里是 32×32 像素），每行字符串长度必须**完全相等**。坐标系是 `grid[y][x]`，左上角是 (0,0)，x 往右、y 往下。

建筑画法惯例（2026-07 新）：一栋可进入的房子是 **2 宽 × 2 高**：上排 `BB`、下排 `BD`（门在左下角）。**门前两格都放传送**（同一室内目标，face [0,-1]）；1 宽的装饰房（单格 B）只放 1 个传送。连片的大 B 块已被淘汰（店铺/宫殿/城门由引擎自动盖多格图，其余 B 格自动填 1x1 民居）。旧惯例：一栋房子是一个矩形 B 块（比如 4 格宽 × 3 格高），最下面那排中间放一格 D 当门。**人进不了 D，触发进屋用的是门前那一格可通行的格子**（见下面"传送"）。

## 二、跳转是怎么触发的（传送机制）

### 1. 传送点 transitions

```js
transitions: [
  { x: 10, y: 17, to: { map: "ch00_field", x: 11, y: 16 } },
]
```

意思：玩家走到本图 (10,17) 这一格上，就瞬间传送到 `ch00_field` 地图的 (11,16) 格。

规则：
- **源格必须可通行**（传送写在 G/C/E/h/草地/路上，不能写在墙/门上）。
- **落点必须可通行**，而且不能正好落在目标图的另一个传送格上（防止来回弹）。
- 可以只写一个格，也可以并排写两格（比如双格城门）。
- 可以加条件：`if: { flag: "q1", exists: true }` —— 某个剧情旗标存在/等于某值/不等于某值时才生效（比如"第一章之后东南门才开"）。

### 2. face：朝门才进

进店传送一般长这样：

```js
{ x: 3, y: 10, face: [0, -1], to: { map: "ch00_inn_in", x: 4, y: 4 } }
```

`face: [0, -1]` 的意思是：**玩家必须正在朝上（北）移动**踩到这格才触发。沿街横着路过不会被吸进店里。门朝南开就 `[0, -1]`，朝东开就 `[1, 0]`，以此类推。
（现在的引擎是宽容版：就算你横着走到门口这格、再顶着门按方向，也会直接进去。）

### 3. 触发器 triggers（踩点剧情）

```js
triggers: [
  { x: 18, y: 16, if: { flag: "river_god", not: "done" },
    do: [{ say: "ch00.riverGod" }, { ask: {...} }] },
]
```

踩到 (18,16) 且条件成立（河神任务没做过）就依次执行 `do` 里的动作：说话、弹选项、给钱、给装备、战斗、切图……`do` 支持的动作：`say`（对话）、`ask`（选项）、`set`（设旗标）、`gold`（给钱）、`give`/`giveEquip`（给道具/装备）、`battle`（战斗）、`warp`（传送）、`join`/`leave`（队友进出）、`minigame`、`chapter`（切章节）、`toast`（飘字提示）等。

### 4. NPC 怎么"会做事"

NPC 声明在 `npcs` 数组，常用字段：

```js
{ id: "inn", x: 4, y: 2, color: "#c98a4b", name: "旅店老板",
  shop: "vil_inn" }                    // 面对按 A：开店（id 指向 items.js 的 SHOPS）
{ id: "camp", x: 16, y: 11, name: "老兵", facility: "camp" }   // 设施：camp 编成所 / smith 铁匠 / tavern 酒馆 / dojo 训练所
{ id: "v1", x: 8, y: 12, name: "村民",
  lines: ["一句台词。"] }              // 静态台词
{ id: "v2", ..., branches: [           // 条件分支台词（剧情 NPC 用这个）
  { if: { flag: "q0", is: "accepted" }, say: "ch00.v1Accepted", do: [{ set: {...} }] },
  { say: "ch00.v1Done" },              // 无条件兜底分支（必须放最后）
] }
{ id: "boss", x: 7, y: 1, name: "黄巾头目", boss: "ch00_boss",
  appearIf: { flag: "q0", is: "accepted" },   // 条件出现；hideIf 条件消失
  onWin: [{ set: { q0: "bossDone" } }] }      // 打赢后执行
```

### 5. 宝箱 chests

```js
chests: [ { x: 13, y: 1, id: "c1", gold: 200 },
          { x: 1, y: 9, id: "c2", items: { "草药": 2, "铜剑": 1 } } ]
```

站旁边面对按 A 开启，开过就消失（引擎按"地图+id"记旗标）。**宝箱格不可通行**，别堵在窄路上；物品名必须在 `data/items.js` 里存在。

### 6. 招牌 signs 与条件地块 tileOverrides

```js
signs: [ { x: 15, y: 1, text: "府", color: "#ffd166" } ]   // 画在建筑顶格的一个字
tileOverrides: [ { x: 3, y: 25, ch: "C", if: { flag: "tavern_clue", exists: true } } ]
// 这格平时是 grid 里写的字符（比如 R 山石），条件成立才变成 C（洞口）
```

> **V4 贴图渲染说明（2026-07 起）**：地图画面已由程序色块升级为 `assets/gfx/v4/` 素材贴图，数据格式不变：
> - 招牌文字为 武/装/客/药/酒/训/编 时，引擎自动在门（D）上方盖 2x2 店铺图（底行压门行），该招牌字随后不再显示；其他文字（如"府"）照常显示。
> - P 横排自动盖 4x2 宫殿、G 横排自动盖 4x2 城门楼；其余未覆盖的 B 块自动填 1x1 民居（村庄地图用乡村款）。
> - 需要特殊摆建筑时，地图可加 `buildings: [{img, x, y, w, h}]`（img 相对 `assets/gfx/v4/`，w/h 为格数，锚定左上角），优先于自动推导。
> - **美术覆盖 tileArt**：地图可加 `tileArt: {"x,y": "v4相对路径.png"}`，把指定格子的贴图整格换掉（字符照旧决定通行性）——自由搭配土路/沙地/草地衔接就靠它，地图编辑器的"素材库"面板刷的就是这个字段。
> - 预览工具：`tools/preview_v4.py <地图key...>` 离线渲染整图 PNG；`tools/cdp_shot.py <地图key,x,y...>` 无头 Edge 实机截图。

## 三、室内图怎么设计（含尺寸建议）

### 现状

- 店铺室内统一 8×6：一圈 B 墙 + L 木地板 + 店主站 (4,2) + 门口 (4,5) 回城。你觉得小，合理——它本来就是"一眼看完"的单间。
- 太守府大殿 11×9：红毯中轴 + 两列 X 殿柱 + 深处 P 宝座。

### 建议尺寸

| 室内类型 | 建议尺寸 | 布局建议 |
|---|---|---|
| 小店铺（村店） | 8×6 ~ 10×7 | 单间：店主 + 柜台感（用 B 横条）+ 一扇窗 |
| 大店铺（城市） | 10×8 ~ 12×9 | 可分两区：前厅柜台 + 后仓货架（B 块当货架，留过道） |
| 民房（无功能） | 7×6 ~ 9×7 | 单间或一小厅：桌椅感（用 B 小块）+ 预留宝箱角 |
| 客栈 | 10×8 ~ 12×9 | 大厅 + 2-3 间客房（小隔断）|
| 府邸/大殿 | 11×9 ~ 14×11 | 中轴红毯 + 柱 + 宝座 |

### 室内图拼装惯例

1. 外围一圈 `B`（墙），内部铺 `L`（木地板）
2. 门口位置：底排中间，回城传送写在门口格（传回城外门口**旁边一格**，不能踩在"进城传送格"上——校验器会报"落点踩在目标图传送块上"）
3. 店主 NPC 站 (4,2) 或柜台后（玩家隔着柜台也能对话）
4. 进屋传送写在城外门口格：`face: [0, -1]`（门朝南时）

### 一张新图要登记三处

1. `index.html`：地图 script 区加一行 `<script src="data/maps/你的图.js"></script>`（放在 `data/chapters.js` 之前）
2. `data/chapters.js`：加进对应章节的 `maps: [...]` 数组
3. 跑 `python tools/validate.py` 自查（行宽、坐标、传送、引用全查）

## 四、手改地图的常见坑

1. **行宽不一致**：grid 每行字符数必须一样（校验器第一项就查这个）。
2. **坐标写反**：永远是 `grid[y][x]`——先想第几行（y），再想行内第几个（x）。
3. **NPC/宝箱堵路**：它们都不可通行，别放在一格宽的通道、门口正前方、传送格上。
4. **传送落点踩传送块**：A→B 的落点不能是 B 图里另一个传送格的坐标。
5. **物品/敌人/台词名字写错**：物品在 `data/items.js`、敌人在 `data/enemies.js`、台词在 `data/text.js`，名字必须存在（校验器会查引用）。
6. 改完**一定跑** `python tools/validate.py`，全绿再进游戏测。
