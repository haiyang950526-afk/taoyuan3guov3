# 09 · UI 改善方案（风格一体化 + 多槽读档）

> 目的：① 让 UI 外壳（对话框、窗口、按钮、标题页）与游戏画面素材"长在一起"——
> 现在画面是像素国风，UI 却是扁平蓝灰 CSS，两种画风；② 读档改为多档位 +
> 二次确认，防止误触毁档/误读档。
>
> **本文档仅为设计稿，尚未接入游戏。** 主程序 agent 按"所需改动"列施工。

### 问题：UI 外壳是另一套画风

`index.html` 里全部 UI 都是扁平 CSS：深蓝灰面板 `#141c30`、圆角 10~14px、
亮蓝描边 `#4f8cff`、按钮 `#24304f` 纯色块。和像素画面拼在一起，像"网页弹窗
贴在游戏上"。涉及处：对话框 `#dialog`、通用面板 `#panel`、战斗日志/指令框
`#battle-log/#battle-cmd`、toast、标题页 `#scr-title`、十字键/AB 键 `#dpad`、
章节插画边框 `#illust`。

### 存档现状

- 单档位：`localStorage["taoyuan3g_save"]`，`engine/save.js` 的
  `saveGame()/loadGame()` 无槽位概念（存档体内已有 `ts` 时间戳，可直接用于档位展示）。
- 标题页 `继续征途（读档）`（`engine/core.js:295`）点击**直读**，无确认；
- 游戏内菜单 `存档/读档`（`engine/ui.js:546-555`）同样直存直读，无确认、无槽位。

## 三、读档多档位 + 确认弹窗（核心需求，P0，不依赖素材）

### 交互流程

```
标题页 / 游戏内菜单
  └─ 点击「继续征途（读档）」
       └─【档位选择层】三个档位卡片（纵向列表）
            ├─ 档位一  第六章 · 新野城  刘备 Lv26  07-26 21:03
            ├─ 档位二  第四章 · 白马坡  关羽 Lv18  07-24 20:41
            └─ 档位三  —— 空档位 ——（置灰不可选）
                 └─ 点击有效档位
                      └─【确认弹窗】（复用通用确认组件）
                           "读取此档？
                            将回到：第六章 · 新野城（刘备 Lv26）
                            当前未保存的进度将丢失。"
                           [ 确认读取 ]  [ 取消 ]
                            └─ 确认 → loadGame(slot) → 进地图
```

- **空档位**：读档流程置灰不可点；存档流程可选（写入新档）。
- **游戏内菜单的「存档」对称改造**：点开同样是三档选择 → 点已占用档位时确认弹窗
  文案改为 `"该档位已有记录（第X章 · 地图名），覆盖？"` [确认覆盖][取消]；
  点空档位直接写入并 toast 成功（新档无损失，无需确认）。
- **取消（B 键 / 点击遮罩）逐层返回**：确认弹窗 → 档位层 → 标题页/菜单。
- 键盘：↑↓ 移动光标（用 `sel_arrow`），Enter/Z 确认，Esc/X 返回——与现有
  操作习惯一致（`index.html` 标题页 hint 文案同步更新）。

### 数据层改动（`engine/save.js`，全部向后兼容）

- 存档键：`taoyuan3g_save_1` / `_2` / `_3`；**旧单档 `taoyuan3g_save` 自动迁入
  档位一后删除旧键**（老玩家进度不丢）。
- `saveGame(slot)` / `loadGame(slot)` / 新增 `listSlots()`：返回三槽元信息
  `{ slot, empty, chapter, map, heroName, heroLv, ts }`（读档时只解析头部字段，
  不做 `applySave`）。
- 档位卡片展示：`第X章 · 地图名 · 队长名 Lv · 存档时间`——所需字段
  `chapter/map/ts` 存档体内已有，`party[0]` 取队长，零新增字段。
- `migrateSave` 逻辑不变，逐槽独立迁移。

### UI 组件改动

- 新增**通用确认弹窗组件** `confirmBox({ title, lines, okText, cancelText, onOk })`
  ——基于现有 `#panel` 实现，z-index 压一层；读档、覆盖存档复用同一个，
  后续删档、 shop 大额购买也能用。
- 档位选择层同样基于 `#panel` 扩展（列表项 = 档位卡片按钮），不写死读档专用。
